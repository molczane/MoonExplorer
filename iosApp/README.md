# Moon Explorer — iOS App

iOS host for the Moon Explorer KMP / Compose Multiplatform spike. The Compose Multiplatform UI lives in `:shared`; this Xcode project hosts the `Shared.framework` and provides the platform Filament renderer per **ADR-0002 §"Bridge pattern: closure injection from Swift"**.

## Prerequisites

- **macOS** with **Xcode 15+** (tested on Xcode 26.2 / iOS 26 SDK).
- **CocoaPods 1.16+** (`brew install cocoapods` or `sudo gem install cocoapods`).
- A configured Apple Developer team. Set `TEAM_ID` in [`Configuration/Config.xcconfig`](Configuration/Config.xcconfig). The wizard ships with `TEAM_ID=` empty — fill in your team ID.
  - Recommended: keep the value local-only via `git update-index --skip-worktree iosApp/Configuration/Config.xcconfig` so the team ID never lands in a commit.

## First-time setup

```sh
cd iosApp
pod install
```

This generates `iosApp.xcworkspace` and downloads the Filament 1.71.1 archives from the upstream podspec at the `v1.71.1` git tag. We point CocoaPods at the raw GitHub URL because Filament's CocoaPods trunk publishing stops at 1.69.3 (see [ADR-0008](../ai-docs/decisions/0008-filament-pod-via-raw-url.md)).

## Building / running

> **Always open `iosApp.xcworkspace`** — never the bare `iosApp.xcodeproj`. CocoaPods integrates the Filament pod into the workspace; opening the project file directly skips it and the build fails to link `_ZSTD_*` symbols.

### From Xcode (recommended)

1. Open `iosApp.xcworkspace`.
2. Choose a destination:
   - **Physical iPhone**: works as-is. Build target is `iosArm64`.
   - **iOS Simulator on Apple Silicon Mac**: must run under **Rosetta**. The Filament pod excludes the `arm64` simulator slice (`EXCLUDED_ARCHS[sdk=iphonesimulator*] = arm64`, see [ADR-0002](../ai-docs/decisions/0002-filament-ios-distribution.md) §"Verification"). Right-click your simulator destination in the Xcode toolbar (or in *Product → Destination → Show All Run Destinations*) → **"Open in Rosetta"**.
   - **iOS Simulator on Intel Mac**: works as-is (uses x86_64 slices).
3. ⌘R to build + run.

### From the command line

```sh
# Physical device (arm64):
xcodebuild -workspace iosApp.xcworkspace -scheme iosApp -sdk iphoneos build

# Simulator under Rosetta (Apple Silicon):
xcodebuild -workspace iosApp.xcworkspace -scheme iosApp \
           -sdk iphonesimulator -arch x86_64 build
```

### Known IDE quirk: IntelliJ IDEA / Fleet KMP plugin

The KMP iOS run-config in IntelliJ IDEA / JetBrains Fleet has a known incompatibility with the CocoaPods workspace — the build fails almost immediately with `Build failed in 14 ms` and no actionable detail in the build log. **Workaround: build iOS from Xcode directly.** Android continues to work fine in IntelliJ / Android Studio.

## Project structure

```
iosApp/
├── Configuration/
│   └── Config.xcconfig           Local-only build settings: TEAM_ID, PRODUCT_BUNDLE_IDENTIFIER
├── iosApp/
│   ├── iOSApp.swift              @main; wires MoonRendererProvider closures from Kotlin → Swift
│   ├── ContentView.swift         SwiftUI host; embeds Compose via MainViewControllerKt.MainViewController()
│   ├── MoonRenderer.h            ObjC interface (Swift sees this only)
│   ├── MoonRenderer.mm           ObjC++ wrapper around Filament's C++ API; <filament/...> includes here
│   ├── MoonRendererView.swift    UIView subclass with CAMetalLayer backing
│   ├── MoonRendererViewController.swift
│   │                             UIViewController owning a MoonRenderer + CADisplayLink
│   ├── KotlinByteArray+Data.swift
│   │                             Kotlin/Native ByteArray ↔ Swift Data bridge
│   ├── iosApp-Bridging-Header.h  Imports MoonRenderer.h for Swift visibility
│   └── Info.plist                CADisableMinimumFrameDurationOnPhone = true (for Filament @ device refresh rate)
├── Podfile                       Filament/filament + Filament/ktxreader + Filament/uberz at ~> 1.71.1
├── Podfile.lock                  Pinned spec graph; commit after pod install
├── Pods/                         (gitignored — regenerated by pod install)
└── iosApp.xcworkspace/           (generated by pod install — open this, not the .xcodeproj)
```

## Updating Filament

1. Bump `filament` in `gradle/libs.versions.toml` (drives the Maven Android dep).
2. Update `FILAMENT_PODSPEC` URL in `iosApp/Podfile` to the new tag.
3. `cd iosApp && pod install`.
4. `./gradlew :shared:downloadFilamentTools` (re-fetches `matc`).
5. Smoke-test on Android + iOS.

See [ADR-0008](../ai-docs/decisions/0008-filament-pod-via-raw-url.md) and [ADR-0002](../ai-docs/decisions/0002-filament-ios-distribution.md) for the full rationale of the distribution model.

## Common pitfalls

- **`Build failed in 14 ms`** — see the IntelliJ/Fleet note above. Build from Xcode.
- **`Undefined symbol: _ZSTD_decompress` etc.** — Podfile is missing `Filament/uberz`. Should already be there per Phase 3 review (commit `bbdfa8c`); re-run `pod install` if your local Podfile.lock is stale.
- **`UnsatisfiedLinkError: nCreateBuilder`** — that's the Android side. Make sure `MoonHost`'s companion-init calls `Filament.init()` before `Engine.create()` (also fixed in `bbdfa8c`).
- **Black screen, no error** — iOS app forgot to wire `MoonRendererProvider.shared.factory` (and friends) in `iOSApp.init()`. The Phase Final guard logs a warning to the Xcode console when this happens. Re-check `iOSApp.swift`.
